## Sorting Algorithms

    Sorting algorithms are used to arrange data in a specific order, usually from smallest to largest or largest to smallest.

    In this implementation, I use several common sorting algorithms: **Bubble Sort, Selection Sort, Insertion Sort, Merge Sort, Quick Sort, Counting Sort, and Bucket Sort**.

    ### Bubble Sort

        Bubble Sort repeatedly compares adjacent elements and swaps them if they are in the wrong order.

        For example:

        ```text
        [5, 3, 8]

        Compare 5 and 3 → swap
        [3, 5, 8]
        ```

        This process continues until the array becomes sorted.

        If the array is already sorted and the implementation stops early, the best case can be **O(n)**. In this implementation, however, there is no early-exit flag, so it still performs all passes.

        **Time Complexity in this implementation: O(n²).**

        **Space Complexity: O(n)** because `self.__array[:]` creates a copy of the array.

    ### Selection Sort

        Selection Sort repeatedly finds the smallest element in the unsorted part of the array and moves it into the correct position.

        For example:

        ```text
        [7, 3, 5, 1]

        Smallest = 1
        Swap with first position

        [1, 3, 5, 7]
        ```

        The algorithm always scans the remaining unsorted elements, even if the array is already sorted.

        **Best Time Complexity: O(n²).**

        **Average Time Complexity: O(n²).**

        **Worst Time Complexity: O(n²).**

        Because this implementation copies the original array first:

        **Space Complexity in this implementation: O(n).**

    ### Insertion Sort

        Insertion Sort builds a sorted section of the array one element at a time.

        It takes the current element and shifts larger elements to the right until the correct position is found.

        For example:

        ```text
        [3, 7, 4]

        Take 4
        Shift 7 right

        [3, 4, 7]
        ```

        If the array is already sorted, each element only needs one comparison.

        **Best Time Complexity: O(n).**

        In the average and worst cases, many elements may need to be shifted.

        **Average Time Complexity: O(n²).**

        **Worst Time Complexity: O(n²).**

        Because this version sorts `self.__array` directly:

        **Space Complexity: O(1).**

    ### Merge Sort

        Merge Sort uses a divide-and-conquer approach.

        It repeatedly divides the array into two halves until each subarray contains only one element.

        For example:

        ```text
        [8, 4, 2, 6]

                [8, 4, 2, 6]
                /        \
            [8, 4]     [2, 6]
            /   \       /   \
            [8]   [4]   [2]   [6]
        ```

        The smaller arrays are then merged back together in sorted order.

        The array is divided into approximately `log n` levels, and at each level all `n` elements are processed during merging.

        **Best Time Complexity: O(n log n).**

        **Average Time Complexity: O(n log n).**

        **Worst Time Complexity: O(n log n).**

        Merge Sort creates new subarrays while dividing and merging.

        **Space Complexity: O(n).**

    ### Quick Sort

        Quick Sort also uses divide and conquer.

        It selects a **pivot**, and the partition function moves smaller values to the left of the pivot and larger values to the right.

        In this implementation, the final element is selected as the pivot:

        ```python
        pivot = array[end]
        ```

        After partitioning, the pivot is already in its final sorted position.

        The algorithm then recursively sorts the left and right sections.

        With good pivots, the array is divided approximately in half each time.

        **Best Time Complexity: O(n log n).**

        **Average Time Complexity: O(n log n).**

        If the pivot repeatedly becomes the smallest or largest value, the partitions can become extremely unbalanced.

        For example:

        ```text
        [1, 2, 3, 4, 5]
        ```

        using the last value as the pivot can produce partitions of size:

        ```text
        4 and 0
        3 and 0
        2 and 0
        1 and 0
        ```

        Therefore:

        **Worst Time Complexity: O(n²).**

        The recursive call stack uses:

        **Average Auxiliary Space Complexity: O(log n).**

        **Worst Auxiliary Space Complexity: O(n).**

        However, this public `quick_sort()` also creates:

        ```python
        array = self.__array[:]
        ```

        so the complete implementation additionally uses an O(n) array copy.

        ### Partition

        The partition function processes the current section of the array once.

        It keeps `i` at the end of the smaller-values section and moves values smaller than the pivot to the left.

        Finally, the pivot is moved to position `i + 1`.

        **Time Complexity: O(n).**

        **Space Complexity: O(1).**

    ### Counting Sort

        Counting Sort does not compare elements directly.

        Instead, it creates a counting array where each index represents a possible value.

        For example:

        ```text
        Input:
        [2, 1, 2, 3]

        Counts:
        index: 0 1 2 3
        count: 0 1 2 1
        ```

        The algorithm then reconstructs the sorted array using those counts.

        If `n` is the number of elements and `k` is the value range:

        **Time Complexity: O(n + k).**

        The counts array requires additional memory proportional to the value range.

        **Space Complexity: O(k).**

        This algorithm is especially useful when the range of integer values is not too large.

    ### Bucket Sort

        Bucket Sort distributes values into several smaller buckets based on their values.

        In this implementation, the number of buckets is equal to the number of elements:

        ```python
        buckets = [[] for _ in range(n)]
        ```

        Each item is assigned to a bucket using:

        ```python
        bucket_index = int(
            item * (n - 1) / max_value
        )
        ```

        This maps the values into valid bucket indexes from `0` to `n - 1`.

        After distribution, each bucket is sorted using Merge Sort.

        Finally, all buckets are combined into one sorted array.

        If the values are distributed well:

        **Distribution Time Complexity: O(n).**

        However, because this implementation sorts each bucket using Merge Sort, the worst case is different from textbook Bucket Sort using Insertion Sort.

        If every value falls into one bucket, Merge Sort sorts that bucket in:

        **Worst Time Complexity: O(n log n).**

        So for this exact implementation:

        **Best/Average Time Complexity: depends on distribution, approximately O(n + bucket sorting cost).**

        **Worst Time Complexity: O(n log n).**

        The buckets and output array store additional elements.

        **Space Complexity: O(n + k).**

        Since this implementation uses `k = n` buckets:

        **Space Complexity simplifies to O(n).**

    ### Overall Comparison

        The main sorting complexities are:

        **Bubble Sort: O(n²) in this implementation.**

        **Selection Sort: O(n²).**

        **Insertion Sort: O(n) best, O(n²) average/worst.**

        **Merge Sort: O(n log n).**

        **Quick Sort: O(n log n) average, O(n²) worst.**

        **Counting Sort: O(n + k).**

        **Bucket Sort in this implementation: up to O(n log n), because Merge Sort is used inside the buckets.**

        For small or nearly sorted arrays, **Insertion Sort** can work very well.

        For larger general-purpose arrays, **Merge Sort** and **Quick Sort** are usually much more efficient than Bubble Sort or Selection Sort.

        **Counting Sort** can be extremely fast when the values are integers within a limited range.

        **Bucket Sort** works best when values are distributed fairly evenly among the buckets.
